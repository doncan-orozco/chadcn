# Chart (shadcn new-york-v4, recharts 3.8.0)

Sources read: `dev/port/oracle/src/chart.tsx` (manifest `source_sha` 35e2fa755465ef8e; shadcn's wrapper: `ChartContainer`, `ChartStyle`, `ChartTooltip` = recharts `Tooltip`, `ChartTooltipContent`, `ChartLegend` = recharts `Legend`, `ChartLegendContent`, the `ChartConfig` type, `THEMES = { light: "", dark: ".dark" }`, `INITIAL_DIMENSION = { width: 320, height: 200 }`), and the library it wraps, `dev/react-shadcn-catalog/node_modules/recharts/es6` (cited as `recharts:<path>:<line>`, recharts 3.8.0 pinned by `package-lock.json`). Numbers and DOM below were measured with `dev/spikes/chart/oracle_ssr.mjs` (settled client render in Chromium; `renderToStaticMarkup` renders an empty `recharts-wrapper`, see `dev/decisions/chart.md`) and reproduced by the spike with a largest deviation of 0.0 px for the bar and line cases.

**No third-party JavaScript** (maintainer constraint of the adoption epic, the same as sonner): recharts is not shipped. The charts are Phlex SVG emitting recharts' DOM, the math is Ruby (core, no Rails), the behavior is `chadcn--chart`. shadcn-port R14 is therefore not followed (`deviations/chart.json`). The chart classes are in the Tailwind class string of `ChartContainer` (`[&_.recharts-cartesian-axis-tick_text]:fill-muted-foreground`, ...), copied verbatim from the oracle, and are the reason the `recharts-*` class names below are part of the contract.

## API

Root `Chadcn::Chart` (namespace and DX-helper root: `Chart.new { |chart| chart.container(config: ...) { ... } }`, `yield self`). Two generated helper sets, never hand-written (shadcn-port R16, see "DX helpers"): the root's (`container`, `style`, `tooltip`, `legend`, `bar_chart`, ..., one per nested `Base` class, generated by `Base.const_added`; `spec_helpers.rb` derives nothing for chart) and each chart class's (`chart.bar`, `chart.x_axis`, ..., one per `Chart::Declaration` subclass, generated by `Declaration.inherited`). Names follow the oracle exports (`ChartContainer` -> `Chart::Container`, `ChartTooltipContent` -> `Chart::Tooltip::Content`) and, for the recharts components the shadcn examples import from `recharts`, the recharts name nested under `Chart` (`BarChart` -> `Chart::BarChart`). **Naming exception (naming-conventions R2, open for the maintainer):** the chart names keep the `Chart` suffix (`Chart::BarChart`, not `Chart::Bar`) because `Chart::Bar`, `Line`, `Area`, `Pie`, `Radar` and `RadialBar` are the series classes of the same React names; de-stuttering would make two React exports share one Ruby constant. String and symbol options are equivalent everywhere (`type: :monotone`, `indicator: "dot"`).

### The recharts layer (what the shadcn examples import from `recharts`)

Three components pass the SVG props (`className`, `id`, `style`, `aria-*`, ... through `svgPropertiesNoEvents`) not to their root group but to the elements they draw, and the port lands `class:`/attrs where recharts does: `CartesianGrid` on every grid `<line>` (`cartesian/CartesianGrid.js:81-93`), `PolarGrid` on every concentric `<circle>`/`<path>` (`polar/PolarGrid.js:81,99`; inputs `:166,183`) and every angle `<line>` (`:36-60`), `LabelList` on each `recharts-label` text it draws (`component/LabelList.js:97-99`, `Label.js:346`). Their root groups (`recharts-cartesian-grid`, `recharts-polar-grid`, `recharts-label-list`) take no caller class. Only `Tooltip` and `Legend` have a fixed wrapper `div` with no `className` (`component/TooltipBoundingBox.js:85-89`, `component/Legend.js:156`); for those `class:` and attrs are a chadcn addition on `recharts-tooltip-wrapper` / `recharts-legend-wrapper` (recorded in `deviations/chart.json`).

R6 exceptions (recorded in `deviations/chart.json`): `Style` takes no attrs and renders a bare `<style>` like `ChartStyle`; `Cell` (and any declaration that renders nothing: `recharts:component/Cell.js:14` is `() => null`) accepts only its documented kwargs (`fill`, `stroke`, `stroke_width`) and rejects any other, `class:` and attrs included, with `ArgumentError`. `Tooltip::Content` and `Legend::Content` do accept `**attrs` on the root `div`, a chadcn addition (React's `ChartTooltipContent`/`ChartLegendContent` do not spread props, `dev/port/oracle/src/chart.tsx`; only `ChartContainer` does, `:70`).

Not ported: the axis `label:` prop (a string, object or element drawn next to an axis; use `Chart::Label` where the host needs one), `Brush`, `ReferenceLine`, `ReferenceArea`, `ReferenceDot`, `ErrorBar`, `Customized`, `ComposedChart`, `Funnel`, `Treemap`, `Sankey`, `Scatter`, `ZAxis`, every prop taking a React element or function other than the named formatters, `ref`, mouse/touch/keyboard callback props (events instead). `Dot` (`dot:` option of Line/Area/Radar) and `ActiveDot` are rendered by the series.

```ruby

```

## Structure (the recharts DOM contract)

### Shell, common to every chart (`dev/spikes/chart/oracle/*.html`)

```html

  <style>\n [data-chart=chart-<id>] {\n  --color-desktop: var(--chart-1);\n}\n\n\n.dark [data-chart=chart-<id>] {\n  --color-desktop: var(--chart-1);\n}\n</style>
  <div class="recharts-responsive-container" style="width: 100%; height: 100%; min-width: 0px;">      <!-- recharts:component/ResponsiveContainer.js:138 -->
    <div style="width: 0px; height: 0px; overflow: visible;">
      <div width="320" height="200" class="recharts-wrapper" style="position: relative; cursor: default; width: 320px; height: 200px;">  <!-- recharts:chart/RechartsWrapper.js:323 -->
        <div xmlns="http://www.w3.org/1999/xhtml" tabindex="-1" class="recharts-tooltip-wrapper ..." style="...">content of the active index</div>   <!-- always present with a Tooltip -->
```

- Order inside `.recharts-wrapper`: tooltip wrapper, legend wrapper, svg (measured; the tooltip wrapper is `visibility: hidden` and empty without an active index; without a `Tooltip` there is no wrapper).
- `svg`: `role="application" tabindex="0"` only with `accessibility_layer` (default true; `recharts:container/RootSurface.js:42-59`); polar charts add `cx="50%" cy="50%"`. `<title></title><desc></desc>` are always present and empty.
- z-index layers, in this order, each `<g tabindex="-1" class="recharts-zIndex-layer_<z>">` (`recharts:zIndex/DefaultZIndexes.js`, `zIndex/ZIndexPortal.js:32`): `-100` grid, `-50` bar background, then `<defs><clipPath id="recharts1-clip"><rect x y height width></clipPath></defs>` (plot rectangle), `100` area (and polar `area` zIndex: pie, radar), `200` cursor rectangle, `300` bar (and radial bar), `400` line, `500` axes, `600` scatter / **line dots**, `1000` active bar, `1100` cursor line, `1200` active dot, `2000` labels (**axis tick labels**).
- `id`s (`recharts-bar-<React useId>`, `recharts1-clip`) are not reproducible; the contract is that references (`url(#...)`) resolve; G2 compares them by order of appearance.
- Plot rectangle (layout, `recharts:state/selectors/...`): `x = margin.left + left axes widths`, `y = margin.top + top axes heights`, `width = W - margin.left - margin.right - axes`, `height = H - margin.top - margin.bottom - x axis height - legend height` (bottom legend). Measured: bar `5,5,310,132` (30 x axis, 28 legend), line `72,0,236,170` (margin `{left: 12, right: 12}` -> top/bottom 0, y axis 60).

### Cartesian axes and grid

- **Numeric axis** (`recharts:state/selectors/axisSelectors.js:730-759` `combineNiceTicks`, `util/scale/getNiceTickValues.js`; rational arithmetic in Ruby): `nice_ticks: :none` computes none. `:auto` (default) uses the **adaptive** step. With an `auto` keyword in the domain (`[0, :auto]`, the y-axis default, and the implicit domain of a stacked chart) ticks = `getNiceTickValues([min, max], tick_count, allow_decimals, mode)` and the domain becomes first..last tick (stacked extent 505 -> 0..600; 305 -> 0, 80, 160, 240, 320). With a `type: :number` axis and an **explicit numeric domain** (`[0, 400]`) ticks = `getTickValuesFixedDomain` (`util/scale/getNiceTickValues.js:233-259`): steps of `adaptive_step((max - min) / (count - 1))` from `min`, then `max` appended (so the last gap can be shorter), every value rounded to an integer when `allow_decimals` is false, reversed when `min > max`; the **domain is kept** (not extended to the ticks). `:adaptive` and `:snap125` force the algorithm for both cases (they require `tick_count`); `:snap125` replaces the step with `getSnap125Step` (`:61-92`: the smallest of 1, 2, 2.5, 5 times a power of ten that is >= the rough step; `allow_decimals: false` ceils it). No nice ticks are computed when: `tick_count` is unset or the domain is not a well-formed number pair (all modes); the scale is not linear (**`:auto` only**: `:adaptive` and `:snap125` do not check the real scale type, `axisSelectors.js:739-746`; the `:auto` branch is `:747-758`); the domain has no `auto` keyword and the axis `type` is not `:number` (all three modes, so `:snap125` on a category axis without an `auto` domain gets none either). `allow_data_overflow: true` keeps data outside an explicit domain unclipped (recharts' `allowDataOverflow`); `include_hidden: true` lets series with `hide: true` contribute to the domain. Range `[plot.bottom, plot.top]`, mapped with `a * (1 - t) + b * t`.
- **Category axis**: band scale for charts with a bar, point scale (bandwidth 0, first/last tick on the plot edges) otherwise; a tick sits at the middle of its band. `padding` shrinks the range.
- **Grid**: `<g class="recharts-cartesian-grid"><g class="recharts-cartesian-grid-horizontal"><line stroke="#ccc" fill="none" x y width height x1 y1 x2 y2>...` (and `-vertical`), `x y width height` = the plot, one line per tick in tick order, y of each tick.

### Bar family (`oracle/bar.html`)

Layer 300, one group per `Bar`, in declaration order:

```html
<g class="recharts-layer recharts-bar" id="recharts-bar-...">
  <g class="recharts-layer recharts-bar-rectangles">
    <g class="recharts-layer">
      <g class="recharts-layer recharts-bar-rectangle"><g class="recharts-layer recharts-inactive-bar">
        <path fill="var(--color-desktop)" name="undefined" x y width height class="recharts-rectangle" d="..."></path>
      </g></g> ...
```

- `x y width height` are rounded to 4 decimals; `name` is literally `"undefined"` for an unnamed bar (recharts renders `String(undefined)`; reproduced). `background` adds `<g class="recharts-layer recharts-bar-background">` in layer -50 (`barBackground`).
- Position (`recharts:state/selectors/combiners/combineAllBarPositions.js:8-72`, `cartesian/Bar.js:556-686`, `util/ChartUtils.js:381`): `band = plot.width / n`, `stacks` = number of distinct stack ids (a series without `stack_id` is its own stack), `gap = bar_gap` (a number, or a percent of the band). **Without `bar_size`** (the default, as the spike implements): `offset = bar_category_gap * band` (`"10%"` -> 0.1); `gap = 0` when `band - 2 * offset - (stacks - 1) * gap <= 0`; `original = (band - 2 * offset - (stacks - 1) * gap) / stacks`, truncated with `>> 0` (`floor`) when `original > 1`; `size = min(original, max_bar_size)` when `max_bar_size` is given (series value, else chart value), else `original`; `x = band_start + offset + (original + gap) * stack_index + (original - size) / 2`. **With `bar_size`** on the first stack (`:14-45`; the other stacks' `bar_size` are read the same way, an unset one counts 0): the group is centred, `sum = Σ sizes + (stacks - 1) * gap`; when `sum >= band` the gap is dropped (`sum -= (stacks - 1) * gap`, then `gap = 0`) and, if `sum` is still `>= band`, every size becomes `0.9 * band / stacks` (`sum = stacks * size`); `x = band_start + (((band - sum) / 2) >> 0) + Σ over previous stacks of (size + gap)`. Stacked series share `x`; `y = scale(y1)`, `height = scale(y0) - scale(y1)` with d3 `stack` rows `[y0, y1]` in series order, offset none.
- `d` is `shape/Rectangle.js getRectanglePath` (`:31-70`) with every number through `round(n, 4)`: array radius `[tl, tr, br, bl]` (each clamped to `min(|w|, |h|) / 2`): `M x,y+tl [A tl,tl,0,0,1,x+tl,y] L x+w-tr,y [A tr,tr,0,0,1,\n        x+w,y+tr] L x+w,y+h-br [A br,br,0,0,1,\n        x+w-br,y+h] L x+bl,y+h [A bl,bl,0,0,1,\n        x,y+h-bl] Z`, an `A` arc only for a radius > 0, the 2nd/3rd/4th arc with the newline and 8 spaces after the comma exactly as the template literal; no radius: `M x,y h w v h h -w Z`; a numeric radius uses the 4-corner template at `:65`. The comparison collapses whitespace.
- Horizontal bars (`layout: :vertical`, the category axis is vertical and bars grow right; probed): the category axis is the `YAxis` and `x = scale(y0)`, `width = scale(y1) - scale(y0)`, `height = size`; the clip rectangle starts at the y axis (`x=65`). `LabelList` renders `<g class="recharts-layer recharts-label-list"><text width height offset x y class="recharts-text recharts-label" text-anchor="start" fill="#808080"><tspan x dy="0.355em">186</tspan></text>`.
- **Tooltip cursor** (layer 200 for bars, `recharts:component/Cursor.js:104`, `util/cursor/getCursorRectangle.js:6-9`): `<path stroke="none" pointer-events="none" width height fill="#ccc" x y class="recharts-rectangle recharts-tooltip-cursor" radius="0" d="M x,y h w v h h -w Z">` with `x = tick.coordinate - band/2`, `y = plot.y + 0.5`, `width = band`, `height = plot.height - 1`; only for the active index, the shadcn CSS repaints `fill` to `muted`.
- Legend: `<div class="recharts-legend-wrapper" style="position: absolute; width: <W - ml - mr>px; height: auto; left: <ml>px; bottom: <mb>px;">` (`recharts:component/Legend.js:44-75,156`; `vertical_align: :top` uses `top`, in a horizontal layout the wrapper is `left: margin.left` at full width for `align: :center` and `:left` (the content centers itself with `justify-center`), `right: margin.right` for `:right`; only `layout: :vertical` with `align: :center` centers the box, `left: (W - box.width) / 2`, `Legend.js:50-62`), content `Legend::Content` over the series payload (`legend_type` not `none`).

## Tooltip (per-index template contract)

recharts computes the tooltip payload in the browser from a redux store; the server cannot know which category is hovered, so the Phlex chart renders **one inert template per category index** and `chadcn--chart` swaps them.

```html
<template data-chadcn--chart-target="tooltipTemplate" data-index="1" data-label="February"
          data-coordinate='{"x":82.5,"y":68.5}' data-cursor='{"tag":"path","attrs":{"x":"56.6667","y":"5.5","width":"51.6667","height":"131","d":"M 56.6667,5.5 h ..."}}'
          data-active-dots='[{"cx":"...","cy":"...","r":"4","fill":"...","stroke":"#fff","stroke-width":"2"}]'>
  <div class="grid min-w-[8rem] ...">...Tooltip::Content for the payload of index 1...</div>
</template>
```

- One template per category (cartesian: tick index; pie / radial bar: item index with `data-coordinate` at the sector centroid), children of the `div[data-slot="chart"]`, after the responsive container. Payload = every non-hidden series at that index, in series order (`item_sorter` applied), `filter_null`, `include_hidden`; `label` = the axis category (or `name_key`); a series with `type: none` is dropped by `Tooltip::Content` itself (`chart.tsx`).
- `.recharts-tooltip-wrapper` is always present (`tabindex="-1" xmlns="http://www.w3.org/1999/xhtml"`, `pointer-events: none; position: absolute; top: 0px; left: 0px`); hidden and empty at rest (`visibility: hidden`). With `default_index:` the server fills it with that template's content and writes `visibility: visible`, plus the cursor / active dots of that index into the SVG (as `oracle/bar.html`). The controller sets `class` modifiers (`recharts-tooltip-wrapper-right|left`, `-top|bottom`), `style` (`transition: transform 400ms; visibility; transform: translate(x px, y px)`, `recharts:component/TooltipBoundingBox.js:69-83`) with `offset` 10 and viewBox clamping (`util/tooltip/translate.js`). G2 does not compare those two attributes, nor the wrapper's `style`, so `visibility: visible` with `default_index` is invisible to the gate: a scenario asserts it through the content node (present and non-empty at rest, compared with the oracle) and `test/chadcn/chart_test.rb` asserts the style string. The controller mounts the template content into the wrapper with `primitives/template_mount.js` and positions the wrapper with recharts' own algorithm (`recharts:util/tooltip/translate.js`: `getTooltipTranslate`, `getTooltipCSSClassName`), ported to a function of the new primitive; it does not use the floating-ui `primitives/positioner.js` (Radix popper, a different algorithm).
- `cursor: false` renders no cursor; `cursor: true` renders the rectangle (bar) or line (line / area) described above; a Hash adds attributes to it.
- The templates are inert (`<template>`): no layout, no a11y tree, no style; `Tooltip::Content` markup inside is the same Ruby component for server and template renders.

## Behavior

Primitives composed: none of the overlay primitives (no portal, focus scope, scroll lock or hide-others). The controller is `chadcn--chart` (`app/javascript/controllers/chadcn/chart_controller.js`, later items), identifier `chadcn--chart` on the `div[data-slot="chart"]`.

- **Accessibility layer** (recharts `accessibilityLayer`, default on; `recharts:container/RootSurface.js:42-59`, `chart/RechartsWrapper.js:251-258`, `state/keyboardEventsMiddleware.js:14-139`): the `svg` is `role="application" tabindex="0"`. `focus` on the chart, when the keyboard interaction is not already active and no index was remembered, activates category index 0 (`:103-125`; a remembered index is not re-activated by focus, the next arrow key moves from it); `blur` deactivates (the index is remembered); `ArrowRight` / `ArrowLeft` move the active index by ±1 times a direction multiplier, stopping at the first / last tick (recharts never reads the DOM `dir`, there is no RTL handling: the multiplier is +1 only when `selectChartDirection` is `left-to-right` (`recharts:state/selectors/axisSelectors.js:1319-1341`, `state/keyboardEventsMiddleware.js:63-66`), that is a horizontal layout with no reversed `XAxis` and the polar layouts; it is -1 for a horizontal layout with any `reversed: true` `XAxis` and **always -1 for `layout: :vertical`**, reversed or not, because only `left-to-right` yields +1; the server computes it as `keyboard_step`); `Enter` toggles the active state of the current index; other keys do nothing; without `accessibility_layer` none of this applies and the `svg` has neither `role` nor `tabindex`. **Escape dismisses the tooltip**: while a tooltip box is mounted recharts listens for `keydown` on `document` and hides the wrapper (`visibility: hidden`) until the active coordinate changes (`recharts:component/TooltipBoundingBox.js:28-62,83`); the port does the same (`keydown@document->chadcn--chart#dismiss`, undone when the active index changes) and does not touch the remembered keyboard index, which also meets WCAG 1.4.13. Activating an index shows its tooltip template, positions the cursor / active dots from the template attributes and dispatches `chadcn--chart:activate`.
- **Pointer**: `pointermove` on the plot (`.recharts-wrapper`) maps `x` (horizontal layout) or `y` (vertical) to the nearest category tick (`recharts:util/getActiveCoordinate.js`, ticks written as `data-chadcn--chart-ticks-value` JSON on `div[data-slot="chart"]`, the controller element; touch input follows `state/touchEventsMiddleware.js:68`, `document.elementFromPoint`), activates it; `pointerleave` deactivates unless `default_index` pins it (a pinned index returns on leave). Pie / radial bar activate by sector (`event.target.closest(".recharts-sector")` with `data-recharts-item-index`). Touch: `pointermove` with `pointerType: touch` takes the same code path (recharts itself maps `touchmove` through `elementFromPoint`); it is covered by `test/javascript/chart.test.mjs`.
- **Values**: `chadcn--chart` has `activeIndex` (Number, default from `default_index`), `layout` (String, `horizontal|vertical`), `keyboardStep` (Number, `1|-1`, computed by the server from `layout` and the `reversed` axes as above), `ticks` (Array), `accessibilityLayer` (Boolean). Targets: `surface` (the `svg`), `tooltip` (the wrapper), `tooltipTemplate`, `cursor`, `activeDots`, `legend`. **Where the wiring lives** (Stimulus reads values only from the controller element): every `data-chadcn--chart-*-value` is written on `div[data-slot="chart"]` and nowhere else; the `svg` carries only `data-chadcn--chart-target="surface"`, and the `.recharts-wrapper` only `data-action`. Actions: `pointermove->chadcn--chart#move`, `pointerleave->#leave`, `focusin->#focus`, `focusout->#blur`, `keydown->#key`, `keydown@document->#dismiss`. Events (bubbling, `detail: { index, label, payload }`): `chadcn--chart:activate`, `chadcn--chart:deactivate`.
- **Re-measure pass**: on connect and after `document.fonts.ready` the controller re-runs `getTicks` collision with measured label sizes and updates label `x`/`y`/visibility, the legend height (and, if it differs from `legend_height:`, the plot is NOT recomputed: documented deviation; the kwarg is how a host aligns the server with its font) and the tooltip position. No `ResizeObserver` (no re-layout on resize).
- **Cleanup** (radix-stimulus R10, stimulus R2-R4): the active template is mounted with `app/javascript/chadcn/primitives/template_mount.js` (`mountTemplate`, a fresh clone per mount, `unmount()` on deactivate) and the Turbo page cache goes through `app/javascript/chadcn/primitives/turbo_cache.js` (`turboCacheRestore`: `teardown` runs synchronously on `turbo:before-cache` and resets the tooltip wrapper / cursor / active dots to the server state, the `default_index` one or hidden, so the snapshot never holds a stale tooltip; `restore` re-applies the live state `SNAPSHOT_TICKS` later; `release()` in `disconnect()`). `disconnect()` also removes every listener (the document `keydown` included); the controller keeps no state outside its values.
- No series animation: the settled state is rendered. The one transition is the tooltip wrapper's `transition: transform 400ms ease`, which recharts applies from `Tooltip`'s own `isAnimationActive: 'auto'` (so it is present in `oracle/bar.html` although the series animation is off) and omits under `prefers-reduced-motion` (`recharts:component/TooltipBoundingBox.js:9-17,68-75`); the controller writes it the same way.

Not expressible in the parity runner (covered in `test/javascript/chart.test.mjs`): the `chadcn--chart:activate` / `:deactivate` events, Turbo cache restore, font-ready re-measure, touch pointers. Expressible, so they are parity scenarios and not JS tests (testing R12): the keyboard direction of a reversed axis (`XAxis` `{"reversed": true}`) and of a vertical layout (`BarChart` `{"layout": "vertical"}`), each with `focus` on `.recharts-surface` plus `press` `ArrowRight` / `ArrowLeft`, and the Escape dismissal (`press` `Escape`).

## Oracle driving

The scenarios are JSON trees (`{"c": "Chart", "props": {...}, "children": [...]}`) rendered by both harnesses, so they cannot carry React elements or functions. A chart scenario is: `Chart` (-> `ChartContainer`, with `config` and `initialDimension` fixed at 320x200 so the measured container equals the initial one) containing one of `BarChart | LineChart | AreaChart | PieChart | RadarChart | RadialBarChart` whose `props.data` is JSON and whose children are the recharts parts above by name with JSON props (`{"c": "Bar", "props": {"dataKey": "desktop", "stackId": "a", "fill": "var(--color-desktop)", "radius": [0, 0, 4, 4]}}`, `{"c": "ChartTooltip", "props": {"defaultIndex": 1, "content": "ChartTooltipContent", "contentProps": {"hideLabel": true}}}`). ## DX helpers

**`spec_helpers.rb` derives nothing for chart**: `helpers_for` returns `nil` (`.claude/scripts/shadcn/spec_helpers.rb:51`) because the oracle exports no `Chart` root (`ChartContainer ChartTooltip ChartTooltipContent ChartLegend ChartLegendContent ChartStyle`), so chart is in the script's `no_parts` and the generated block is not written into this spec. `test/chadcn/chart_test.rb` is the only gate for the helpers below. Two generated sets (shadcn-port R16), neither hand-written:

1. **`Chart` root**, from `Chadcn::Base.const_added` (`lib/chadcn/base.rb:49-69`), which defines one root helper per **nested `Base` class**, not per oracle export: `container`, `style`, `tooltip`, `legend`, `bar_chart`, `line_chart`, `area_chart`, `pie_chart`, `radar_chart`, `radial_bar_chart`, and, because the declarations are also nested `Base` classes (`Chart::Bar`, ...), `bar`, `line`, `area`, `pie`, `cell`, `radar`, `radial_bar`, `x_axis`, `y_axis`, `cartesian_grid`, `polar_grid`, `polar_angle_axis`, `polar_radius_axis`, `label_list`, `label` (and `declaration` for the abstract base unless item #45 keeps it out of `Chart`; a declaration rendered outside a chart has nothing to register with, which #45 decides how to treat). Parts get their helper on their own namespace: `Chart::Tooltip::Content` yields `Chart::Tooltip#content` and `Chart::Legend::Content` yields `Chart::Legend#content`; there is **no** root `tooltip_content` / `legend_content`. `Chart::Config` is not a `Base` and has none. Helper names that shadow Phlex HTML elements (`style`, `legend`, `area`, `label`; `const_added` allows HTML element names, it raises for any other Phlex/Object method) are shadowed inside `Chart`'s own `view_template`, which therefore uses `tag(:style)` or explicit `render ...new` calls; the SVG itself is emitted by a separate surface component, not by `Chart` or by the chart classes' own view.
2. **Each chart class** (`BarChart`, `LineChart`, `AreaChart`, `PieChart`, `RadarChart`, `RadialBarChart`) yields itself and carries one helper per `Chart::Declaration` subclass: `bar`, `line`, `area`, `pie`, `cell`, `radar`, `radial_bar`, `x_axis`, `y_axis`, `cartesian_grid`, `polar_grid`, `polar_angle_axis`, `polar_radius_axis`, `tooltip`, `legend`, `label_list`, `label`. `const_added` cannot generate these (declarations are nested in `Chart`, not in the chart classes), so this is **new generator work: `Chart::Declaration.inherited` defines the helper on every chart class** (items #45 / #48). Each equals `render Chart::<Class>.new(...)`, so the example above renders the same HTML as the explicit calls.

`test/chadcn/chart_test.rb` asserts both sets: set (1) against the nested `Base` classes of `Chart` (a new nested class without a helper, or a helper without a class, fails), set (2) against `Chart::Declaration.descendants` (same rule), and that every helper renders the same HTML as the explicit `render ...new`.
