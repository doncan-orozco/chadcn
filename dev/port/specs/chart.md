# Chart (shadcn new-york-v4, recharts 3.8.0)

Sources read: `dev/port/oracle/src/chart.tsx` (manifest `source_sha` 35e2fa755465ef8e; shadcn's wrapper: `ChartContainer`, `ChartStyle`, `ChartTooltip` = recharts `Tooltip`, `ChartTooltipContent`, `ChartLegend` = recharts `Legend`, `ChartLegendContent`, the `ChartConfig` type, `THEMES = { light: "", dark: ".dark" }`, `INITIAL_DIMENSION = { width: 320, height: 200 }`), and the library it wraps, `dev/react-shadcn-catalog/node_modules/recharts/es6` (cited as `recharts:<path>:<line>`, recharts 3.8.0 pinned by `package-lock.json`). Numbers and DOM below were measured with `dev/spikes/chart/oracle_ssr.mjs` (settled client render in Chromium; `renderToStaticMarkup` renders an empty `recharts-wrapper`, see `dev/decisions/chart.md`) and reproduced by the spike with a largest deviation of 0.0 px for the bar and line cases.

**No third-party JavaScript** (maintainer constraint of the adoption epic, the same as sonner): recharts is not shipped. The charts are Phlex SVG emitting recharts' DOM, the math is Ruby (core, no Rails), the behavior is `chadcn--chart`. shadcn-port R14 is therefore not followed (`deviations/chart.json`). The chart classes are in the Tailwind class string of `ChartContainer` (`[&_.recharts-cartesian-axis-tick_text]:fill-muted-foreground`, ...), copied verbatim from the oracle, and are the reason the `recharts-*` class names below are part of the contract.

## API

Root `Chadcn::Chart` (namespace and DX-helper root: `Chart.new { |chart| chart.container(config: ...) { ... } }`, `yield self`). Two generated helper sets, never hand-written (shadcn-port R16, see "DX helpers"): the root's (`container`, `style`, `tooltip`, `legend`, `bar_chart`, ..., one per nested `Base` class, generated by `Base.const_added`; `spec_helpers.rb` derives nothing for chart) and each chart class's (`chart.bar`, `chart.x_axis`, ..., one per `Chart::Declaration` subclass, generated by `Declaration.inherited` onto the module `Chart::Declarations` that every chart class includes, see "DX helpers"). Names follow the oracle exports (`ChartContainer` -> `Chart::Container`, `ChartTooltipContent` -> `Chart::Tooltip::Content`) and, for the recharts components the shadcn examples import from `recharts`, the recharts name nested under `Chart` (`BarChart` -> `Chart::BarChart`). **Naming exception (naming-conventions R2, open for the maintainer):** the chart names keep the `Chart` suffix (`Chart::BarChart`, not `Chart::Bar`) because `Chart::Bar`, `Line`, `Area`, `Pie`, `Radar` and `RadialBar` are the series classes of the same React names; de-stuttering would make two React exports share one Ruby constant. String and symbol options are equivalent everywhere (`type: :monotone`, `indicator: "dot"`).

### The recharts layer (what the shadcn examples import from `recharts`)

Chart children are **declarations**: the block of a chart is evaluated first, each child (`Chart::Bar`, `Chart::XAxis`, ...) renders nothing where it is written and registers itself with its chart (a `Chart::Declaration` base), then the chart lays out and emits the SVG. Order of declaration is z-order inside a layer (as in React). Defaults equal recharts' (citations are the `default*Props`).

**`**attrs` / `class:`** (shadcn-port R2-R6, every class `< Chadcn::Base`, `class` through `cn` last, `data:`/`aria:` deep-merged through `merge_attrs`; the one exception below): on a chart class `class:` and `style:` land on `.recharts-wrapper` (`class` after `recharts-wrapper`, `style` merged after the size, `recharts:chart/RechartsWrapper.js:323-329`) and **every other attribute** (`id`, `role`, `tab_index`, `aria-*`, `data-*`; recharts keeps SVG props and `data-*` through `svgPropertiesNoEvents`, `chart/CategoricalChart.js:1,24,35`, `util/svgPropertiesNoEvents.js:32-44`) on `svg.recharts-surface` (`container/RootSurface.js:43-55`, `Surface.js`); `role:` (a String) and `tab_index:` (a Number) override the `application` / `0` defaults of the accessibility layer (`RootSurface.js:43-55`), `title:` / `desc:` fill `<title>` / `<desc>` (`Surface.js:42`; both empty when not given); a series (`Bar`, `Line`, `Area`, `Pie`, `Radar`, `RadialBar`) on its group `recharts-layer recharts-<item>` (`recharts-bar` `cartesian/Bar.js:469`, `recharts-line` `Line.js:516`, `recharts-area` `Area.js:498`, `recharts-pie` `polar/Pie.js:579`, `recharts-radar` `polar/Radar.js:393`; **`RadialBar` uses `recharts-area`**, `polar/RadialBar.js:285`, verified against the HTML) through recharts' own `className` prop; an axis on `recharts-cartesian-axis` (`cartesian/CartesianAxis.js:428`) or `recharts-polar-angle-axis` / `recharts-polar-radius-axis` (`polar/PolarAngleAxis.js:252`, `PolarRadiusAxis.js:196`); `Label` on its `recharts-label` text (`component/Label.js:346`).

Three components pass the SVG props (`className`, `id`, `style`, `aria-*`, ... through `svgPropertiesNoEvents`) not to their root group but to the elements they draw, and the port lands `class:`/attrs where recharts does: `CartesianGrid` on every grid `<line>` (`cartesian/CartesianGrid.js:81-93`), `PolarGrid` on every concentric `<circle>`/`<path>` (`polar/PolarGrid.js:81,99`; inputs `:166,183`) and every angle `<line>` (`:36-60`), `LabelList` on each `recharts-label` text it draws (`component/LabelList.js:97-99`, `Label.js:346`). Their root groups (`recharts-cartesian-grid`, `recharts-polar-grid`, `recharts-label-list`) take no caller class. Only `Tooltip` and `Legend` have a fixed wrapper `div` with no `className` (`component/TooltipBoundingBox.js:85-89`, `component/Legend.js:156`); for those `class:` and attrs are a chadcn addition on `recharts-tooltip-wrapper` / `recharts-legend-wrapper` (recorded in `deviations/chart.json`).

R6 exception (recorded in `deviations/chart.json`): `Style` takes no attrs and renders a bare `<style>` like `ChartStyle`. `Cell` is **not** an exception: it renders nothing itself (`recharts:component/Cell.js:14` is `() => null`) but its props are spread into the parent's shape at its index (`polar/Pie.js:378,407`, `cartesian/Bar.js:683`), so it takes `**attrs` and `class:` like every part and the parent lands them on that sector / rectangle. `Tooltip::Content` and `Legend::Content` do accept `**attrs` on the root `div`, a chadcn addition (React's `ChartTooltipContent`/`ChartLegendContent` do not spread props, `dev/port/oracle/src/chart.tsx`; only `ChartContainer` does, `:70`).

Not ported: the axis `label:` prop (a string, object or element drawn next to an axis; use `Chart::Label` where the host needs one), `Brush`, `ReferenceLine`, `ReferenceArea`, `ReferenceDot`, `ErrorBar`, `Customized`, `ComposedChart`, `Funnel`, `Treemap`, `Sankey`, `Scatter`, `ZAxis`, every prop taking a React element or function other than the named formatters, `ref`, mouse/touch/keyboard callback props (events instead), `active_bar:` other than `false` (needs a per-index shape in layer 1000), the default contents `DefaultTooltipContent` / `DefaultLegendContent` (a `Tooltip` or `Legend` without `content:` renders an empty wrapper; `item_style`, `label_style`, `wrapper_class_name`, `label_class_name` exist only for them and are not accepted; `icon_size`, `icon_type`, `inactive_color`, `separator`, `content_style`, `item_sorter` are accepted for API parity and ignored, see the Legend / Tooltip note above), `Tooltip` `portal` / `use_translate3d`, `Legend` `portal`, `payload_uniq_by` as a function. `Dot` (`dot:` option of Line/Area/Radar) and `ActiveDot` are rendered by the series.

### Cartesian axes and grid

- **Numeric axis** (`recharts:state/selectors/axisSelectors.js:730-759` `combineNiceTicks`, `util/scale/getNiceTickValues.js`; rational arithmetic in Ruby): `nice_ticks: :none` computes none. `:auto` (default) uses the **adaptive** step. With an `auto` keyword in the domain (`[0, :auto]`, the y-axis default, and the implicit domain of a stacked chart) ticks = `getNiceTickValues([min, max], tick_count, allow_decimals, mode)` and the domain becomes first..last tick (stacked extent 505 -> 0..600; 305 -> 0, 80, 160, 240, 320). With a `type: :number` axis and an **explicit numeric domain** (`[0, 400]`) ticks = `getTickValuesFixedDomain` (`util/scale/getNiceTickValues.js:233-259`): steps of `adaptive_step((max - min) / (count - 1))` from `min`, then `max` appended (so the last gap can be shorter), every value rounded to an integer when `allow_decimals` is false, reversed when `min > max`; the **domain is kept** (not extended to the ticks). `:adaptive` and `:snap125` force the algorithm for both cases (they require `tick_count`); `:snap125` replaces the step with `getSnap125Step` (`:61-92`: the smallest of 1, 2, 2.5, 5 times a power of ten that is >= the rough step; `allow_decimals: false` ceils it). No nice ticks are computed when: `tick_count` is unset or the domain is not a well-formed number pair (all modes); the scale is not linear (**`:auto` only**: `:adaptive` and `:snap125` do not check the real scale type, `axisSelectors.js:739-746`; the `:auto` branch is `:747-758`); the domain has no `auto` keyword and the axis `type` is not `:number` (all three modes, so `:snap125` on a category axis without an `auto` domain gets none either). `allow_data_overflow: true` keeps data outside an explicit domain unclipped (recharts' `allowDataOverflow`); `include_hidden: true` lets series with `hide: true` contribute to the domain. Range `[plot.bottom, plot.top]`, mapped with `a * (1 - t) + b * t`.
- **Category axis**: band scale for charts with a bar, point scale (bandwidth 0, first/last tick on the plot edges) otherwise; a tick sits at the middle of its band. `padding` shrinks the range.
- **Grid**: `<g class="recharts-cartesian-grid"><g class="recharts-cartesian-grid-horizontal"><line stroke="#ccc" fill="none" x y width height x1 y1 x2 y2>...` (and `-vertical`), `x y width height` = the plot, one line per tick in tick order, y of each tick.
- **Axis** (`recharts:cartesian/CartesianAxis.js`): in layer 500 `<g class="recharts-layer recharts-cartesian-axis recharts-xAxis xAxis">` containing, when `axis_line`, `<line class="recharts-cartesian-axis-line" stroke="#666" fill="none" x1 y1 x2 y2>`, then `<g class="recharts-cartesian-axis-ticks recharts-xAxis-ticks"><g class="recharts-cartesian-axis-tick-lines recharts-xAxis-tick-lines">` with one `<g class="recharts-layer recharts-cartesian-axis-tick">` per visible tick (holding `<line class="recharts-cartesian-axis-tick-line" stroke="#666" fill="none" x1 y1 x2 y2>` when `tick_line`, empty otherwise). In layer 2000: `<g class="recharts-cartesian-axis-tick-labels recharts-xAxis-tick-labels">` with `<g class="recharts-layer recharts-cartesian-axis-tick-label"><text [orientation, width, height] stroke="none" x y class="recharts-text recharts-cartesian-axis-tick-value" text-anchor="middle|end|start" fill="#666"><tspan x dy="0.71em|0.355em">label</tspan></text></g>` per tick (x axes `dy 0.71em`, y axes `0.355em`; `text-anchor` `middle` for top/bottom, `end` for left, `start` for right). Label position `getTickLineCoord` (`recharts:cartesian/CartesianAxis.js:125-172`): bottom axis `y = axis.y + tick_size + tick_margin`, left axis `x = axis.x + width - tick_size - tick_margin`; both apply even with `tick_line: false`.
- **Label collision / clamping** (`recharts:cartesian/getTicks.js:11-57,125-180`, `interval: :preserve_end`): the last tick's `tickCoord` is pulled inside the viewBox by half its measured size, then ticks are kept/hidden walking backwards with `min_tick_gap`. Size = measured text width (x axes) or height (y axes); measured example: the top y label (`320`, coordinate 0) is drawn at `y = 8`. A numeric `interval` keeps every n+1-th tick and measures nothing.

### Bar family (`oracle/bar.html`)

Layer 300, one group per `Bar`, in declaration order:

```html
<g class="recharts-layer recharts-bar" id="recharts-bar-...">
  <g class="recharts-layer recharts-bar-rectangles">
    <g class="recharts-layer">
      <g class="recharts-layer recharts-bar-rectangle"><g class="recharts-layer recharts-inactive-bar">
```

- `x y width height` are rounded to 4 decimals; `name` is literally `"undefined"` for an unnamed bar (recharts renders `String(undefined)`; reproduced). `background` adds `<g class="recharts-layer recharts-bar-background">` in layer -50 (`barBackground`).
- Position (`recharts:state/selectors/combiners/combineAllBarPositions.js:8-72`, `cartesian/Bar.js:556-686`, `util/ChartUtils.js:381`): `band = plot.width / n`, `stacks` = number of distinct stack ids (a series without `stack_id` is its own stack), `gap = bar_gap` (a number, or a percent of the band). **Without `bar_size`** (the default, as the spike implements): `offset = bar_category_gap * band` (`"10%"` -> 0.1); `gap = 0` when `band - 2 * offset - (stacks - 1) * gap <= 0`; `original = (band - 2 * offset - (stacks - 1) * gap) / stacks`, truncated with `>> 0` (`floor`) when `original > 1`; `size = min(original, max_bar_size)` when `max_bar_size` is given (series value, else chart value), else `original`; `x = band_start + offset + (original + gap) * stack_index + (original - size) / 2`. **With `bar_size`** on the first stack (`:14-45`; the other stacks' `bar_size` are read the same way, an unset one counts 0): the group is centred, `sum = Σ sizes + (stacks - 1) * gap`; when `sum >= band` the gap is dropped (`sum -= (stacks - 1) * gap`, then `gap = 0`) and, if `sum` is still `>= band`, every size becomes `0.9 * band / stacks` (`sum = stacks * size`); `x = band_start + (((band - sum) / 2) >> 0) + Σ over previous stacks of (size + gap)`. Stacked series share `x`; `y = scale(y1)`, `height = scale(y0) - scale(y1)` with d3 `stack` rows `[y0, y1]` in series order, offset none.
- `d` is `shape/Rectangle.js getRectanglePath` (`:31-70`) with every number through `round(n, 4)`: array radius `[tl, tr, br, bl]` (each clamped to `min(|w|, |h|) / 2`): `M x,y+tl [A tl,tl,0,0,1,x+tl,y] L x+w-tr,y [A tr,tr,0,0,1,\n        x+w,y+tr] L x+w,y+h-br [A br,br,0,0,1,\n        x+w-br,y+h] L x+bl,y+h [A bl,bl,0,0,1,\n        x,y+h-bl] Z`, an `A` arc only for a radius > 0, the 2nd/3rd/4th arc with the newline and 8 spaces after the comma exactly as the template literal; no radius: `M x,y h w v h h -w Z`; a numeric radius uses the 4-corner template at `:65`. The comparison collapses whitespace.
- Horizontal bars (`layout: :vertical`, the category axis is vertical and bars grow right; probed): the category axis is the `YAxis` and `x = scale(y0)`, `width = scale(y1) - scale(y0)`, `height = size`; the clip rectangle starts at the y axis (`x=65`). `LabelList` renders `<g class="recharts-layer recharts-label-list"><text width height offset x y class="recharts-text recharts-label" text-anchor="start" fill="#808080"><tspan x dy="0.355em">186</tspan></text>`.
- **Tooltip cursor** (layer 200 for bars, `recharts:component/Cursor.js:66-71,104`, `util/cursor/getCursorRectangle.js:6-9`): `<path stroke="none" pointer-events="none" width height fill="#ccc" x y class="recharts-rectangle recharts-tooltip-cursor" radius="0" d="M x,y h w v h h -w Z">` with `x = tick.coordinate - band/2`, `y = plot.y + 0.5`, `width = band`, `height = plot.height - 1`; only for the active index, the shadcn CSS repaints `fill` to `muted`.
- Legend: `<div class="recharts-legend-wrapper" style="position: absolute; width: <W - ml - mr>px; height: auto; left: <ml>px; bottom: <mb>px;">` (`recharts:component/Legend.js:44-75,156`; `vertical_align: :top` uses `top`, in a horizontal layout the wrapper is `left: margin.left` at full width for `align: :center` and `:left` (the content centers itself with `justify-center`), `right: margin.right` for `:right`; only `layout: :vertical` with `align: :center` centers the box, `left: (W - box.width) / 2`, `Legend.js:50-62`), content `Legend::Content` over the series payload (`legend_type` not `none`).

## Tooltip (per-index template contract)

recharts computes the tooltip payload in the browser from a redux store; the server cannot know which category is hovered, so the Phlex chart renders **one inert template per tooltip index** and `chadcn--chart` swaps them.

```html
<template data-chadcn--chart-target="tooltipTemplate" data-index="1" data-label="February"
          data-coordinate='{"x":82.5,"y":68.5}' data-cursor='{"tag":"path","layer":200,"attrs":{"x":"56.6667","y":"5.5","width":"51.6667","height":"131","d":"M 56.6667,5.5 h ..."}}'
          data-active-dots='[{"cx":"...","cy":"...","r":"4","fill":"...","stroke":"#fff","stroke-width":"2"}]'
          data-payload='[{"name":"desktop","dataKey":"desktop","value":305,"color":"var(--color-desktop)"}]'>
  <div class="grid min-w-[8rem] ...">...Tooltip::Content for the payload of index 1...</div>
</template>
```

- **Which templates.** The event type decides (`tooltipEventType`): `axis` (the default of Bar, Line, Area, Radar and RadialBar charts) renders one template per category, `data-index` = the tick index; `item` (`PieChart` always; a `BarChart` with `Tooltip shared: false`, `state/selectors/selectTooltipEventType.js:4-13`) renders no template yet: the wrapper is hidden and empty, there is no `default_index`, and `tooltipEventType` is `item`, so the controller is inert (a `LineChart` and an `AreaChart` allow `axis` only and keep it). All are children of the `div[data-slot="chart"]`, after the responsive container. **Cost**: the content of `oracle/bar.html` (2 series, `hide_label`) is 1,247 bytes, so a template is about 1.7 KB with its `data-*` attributes and grows with the series; 12 categories are about 20 KB. The gem sets no cap (a `Tooltip` is optional; a host with hundreds of categories pays per category and may drop the `Tooltip`).
- **Payload** of a template = the series at that index **in series order, not sorted**: `item_sorter` is applied only inside `DefaultTooltipContent` (`recharts:component/DefaultTooltipContent.js:76`), while a custom content gets the payload unsorted (`component/Tooltip.js:138-152,170`), so `item_sorter:` is accepted and ignored with `Tooltip::Content`. The server applies `filter_null` (entries whose value is nil are dropped) and drops `hide: true` series unless `include_hidden` (`Tooltip.js:142`). The payload entry `type` is the series' **`tooltip_type`** (`cartesian/Bar.js:85,706`, `Line.js:97`, `Area.js:109`, `polar/Pie.js:129,393`, `Radar.js:86`, `RadialBar.js:230`); `Tooltip::Content` drops an entry whose type is `none` itself (`chart.tsx:200`), the template keeps it, so a series is silenced with `tooltip_type: :none` (there is no `type:` kwarg on `Tooltip`). The label is `data-label` for axis tooltips only (`label: tooltipEventType === 'axis' ? label : undefined`, `Tooltip.js:131`; an item tooltip, a pie, passes **no label**, so `Tooltip::Content` falls back to the first item's config label); `Tooltip::Content` resolves it from `label_key` (the config lookup key, `chart.tsx:154-159`: with no `label_key` and a string label, `config[label]?.label ?? label`), `name_key` only selects the item names.
- `.recharts-tooltip-wrapper` is always present (`tabindex="-1" xmlns="http://www.w3.org/1999/xhtml"`, `pointer-events: none; position: absolute; top: 0px; left: 0px`); hidden and empty at rest (`visibility: hidden`). With `default_index:` the server fills it with that template's content and writes `visibility: visible`, plus the cursor / active dots of that index into the SVG (as `oracle/bar.html`). The controller sets `class` modifiers (`recharts-tooltip-wrapper-right|left`, `-top|bottom`) and `style` (`visibility`, `transform: translate(x px, y px)`, and the transition below, `recharts:component/TooltipBoundingBox.js:54-84`) with `offset` (10, number or `{x, y}`), `allow_escape_view_box`, `reverse_direction` and `position` honored by recharts' own algorithm (`util/tooltip/translate.js`); `wrapper_style` is applied last and wins (`TooltipBoundingBox.js:82-84`). **Transition**: `transition: transform 400ms ease` (`animation_duration` / `animation_easing`) is present **only while the tooltip is active** and `is_animation_active` is true or `auto` and, for `auto`, the user does not prefer reduced motion (`TooltipBoundingBox.js:9-17`); Chromium serializes it as `transform 400ms` (the `ease` initial value is dropped, which is what `oracle/bar.html` shows), the controller assigns `el.style.transition = "transform 400ms ease"`. G2 does not compare the wrapper's `style` and class modifiers, so `visibility: visible` with `default_index` is invisible to the gate: a scenario asserts it through the content node (present and non-empty at rest, compared with the oracle) and `test/chadcn/chart_test.rb` asserts the style string. The controller mounts the template content into the wrapper with `primitives/template_mount.js` and positions the wrapper with recharts' own algorithm (`getTooltipTranslate`, `getTooltipCSSClassName`), ported to a function of the new primitive; it does not use the floating-ui `primitives/positioner.js` (Radix popper, a different algorithm).
- `data-cursor.layer` is the z-index layer group the cursor is drawn in (`g.recharts-zIndex-layer_200` behind the bars, `_1100` for a line or area, the same numbers the server uses for the `default_index` cursor); the controller finds the group by its class list, never through a selector built from data. `data-payload` is what `chadcn--chart:activate` hands to a host as `detail.payload`: one `{name, dataKey, value, color, type, unit}` per series (nil keys dropped), **without** the data row (the row would double every template); the label is `data-label`.
- `cursor: false` renders no cursor; `cursor: true` renders the rectangle (bar chart) or line (line / area) described above; a Hash adds attributes to it. In recharts 3.8 the cursor is always one `<path>` (`Rectangle`, `Curve` or, for a radial layout, `Sector`; `component/Cursor.js:66-94`), the active dots are `<circle>`s. **`data-cursor` / `data-active-dots` are built by the controller with `document.createElementNS("http://www.w3.org/2000/svg", tag)` from a whitelist of tag names (`path`, `circle`; anything else is ignored) and `setAttribute` for a whitelist of SVG presentation / geometry attributes, never `on*`, `href`, `style` or `innerHTML`** (the template content is HTML-parsed, so an SVG fragment cannot live in it unwrapped; the JSON route avoids the namespace problem).
- The templates are inert (`<template>`): no layout, no a11y tree, no style; `Tooltip::Content` markup inside is the same Ruby component for server and template renders. A `formatter:` / `label_formatter:` set on `Chart::Tooltip` overrides the one of its `content:` (see `Tooltip::Content`).

## Behavior

Primitives composed: none of the overlay primitives (no portal, focus scope, scroll lock or hide-others). The controller is `chadcn--chart` (`app/javascript/controllers/chadcn/chart_controller.js`), identifier `chadcn--chart` on the `div[data-slot="chart"]`.

- **Accessibility layer** (recharts `accessibilityLayer`, default on; `recharts:container/RootSurface.js:42-59`, `chart/RechartsWrapper.js:251-258`, `state/keyboardEventsMiddleware.js:14-139`): the `svg` is `role="application" tabindex="0"`. `focus` on the chart, when the keyboard interaction is not already active and **no keyboard index was remembered** (`keyboardIndex` unset, **whether or not `default_index` is set**: the keyboard index is a state of its own), activates category index 0 (`:104-126`; a remembered index is not re-activated by focus, the next arrow key moves from it); `blur` deactivates (the index is remembered); `ArrowRight` / `ArrowLeft` move the active index by ±1 times a direction multiplier, stopping at the first / last tick (recharts never reads the DOM `dir`, there is no RTL handling: the multiplier is +1 only when `selectChartDirection` is `left-to-right` (`recharts:state/selectors/axisSelectors.js:1319-1341`, `state/keyboardEventsMiddleware.js:63-66`), that is a horizontal layout with no reversed `XAxis` and the polar layouts; it is -1 for a horizontal layout with any `reversed: true` `XAxis` and **always -1 for `layout: :vertical`**, reversed or not, because only `left-to-right` yields +1; the server computes it as `keyboard_step`); `Enter` toggles the active state of the current index; other keys do nothing; without `accessibility_layer` none of this applies and the `svg` has neither `role` nor `tabindex`. The middleware resolves **`axis`** coordinates (`keyboardEventsMiddleware.js:55,70`) while `PieChart` is item-only, so keyboard support on a `PieChart` is **unverified until probed** (the pie item must probe it before claiming it; the claim here covers the axis charts). **Escape dismisses the tooltip**: while a tooltip box is mounted recharts listens for `keydown` on `document` and hides the wrapper (`visibility: hidden`) until the active **coordinate** changes (`recharts:component/TooltipBoundingBox.js:28-62,83`); the port does the same (`keydown@document->chadcn--chart#dismiss`, undone when the active coordinate changes) and does not touch the remembered keyboard index, which also meets WCAG 1.4.13. Activating an index shows its tooltip template, positions the cursor / active dots from the template data and dispatches `chadcn--chart:activate`.
- **Pointer**: `pointermove` on the plot (`.recharts-wrapper`) maps `x` (horizontal layout) or `y` (vertical) to the nearest category tick (`recharts:util/getActiveCoordinate.js`, ticks written as `data-chadcn--chart-ticks-value` JSON on `div[data-slot="chart"]`, the controller element) and activates it for an `axis` tooltip; for an `item` tooltip (pie, `shared: false`) it activates by sector (`event.target.closest(".recharts-sector")` with `data-recharts-item-index`; in 3.8 only `Pie` writes that attribute, `util/Constants.js`, `polar/Pie.js`, so item activation on Bar / RadialBar rectangles is **unverified until probed**). With `trigger: :click` the same mapping runs on `click` instead of `pointermove` (recharts keeps a separate click interaction, `combineTooltipInteractionState.js:7-18`). Touch: `pointermove` with `pointerType: touch` takes the same code path (recharts maps `touchmove` to the axis index by the touch coordinate, `state/touchEventsMiddleware.js:45-60`; **`document.elementFromPoint` is used only for item tooltips**, `:62-71`); it is covered by `test/javascript/chart.test.mjs`. As built (item #50, each rule checked against recharts 3.8): a mouse over the margin of the SVG but outside the plot rectangle clears the hover (`state/mouseEventsMiddleware.js:90-93`) while a touch outside does nothing (`state/touchEventsMiddleware.js:49-64`); the pointer coordinate is `{x: tick, y: pointer}` in a horizontal layout and `{x: pointer, y: tick}` in a vertical one (`util/getActiveCoordinate.js:8-28`), so the wrapper follows the pointer along the other axis; `pointerleave` clears the hover only (`state/tooltipSlice.js:156-166`), so with `trigger: click` leaving the chart does not hide the tooltip, and a finger lifting (`pointerleave` with `pointerType: touch`) is ignored because recharts has no touch end handler (`chart/RechartsWrapper.js:309-315`); a touch moves the *hover* interaction whatever `trigger` is, so with `trigger: click` it shows nothing until the tap's click. Touch scrubbing follows the browser's pointer-event rules (a pan that scrolls ends in `pointercancel`; the controller does not set `touch-action`, which would change a compared style). `tooltipEventType: item` is **not wired** (pie, a `BarChart` with `shared: false`): the controller does nothing for it until the polar item probes it, and a `BarChart` `shared: false` renders the hidden empty wrapper only.
- **Active index precedence and `default_index`** (`recharts:state/selectors/combiners/combineTooltipInteractionState.js:19-58`, `state/tooltipSlice.js:147-149,156-166,179-183`): three independent states, not one index. The tooltip shows (1) the **pointer** index while the pointer is active; else (2) the **keyboard** index while keyboard interaction is active; else (3) `default_index`, **only while the pointer has never activated an index** (`hasBeenActivePreviously` = the pointer interaction's index is set); once it has, with `active: true` the tooltip stays at the last pointer index, otherwise nothing is shown. `pointerleave` clears only the pointer's *active* flag and **keeps its index** (`mouseLeaveChart`), so **after the first hover `default_index` never returns**, not even after leaving (a pinned index does not come back on leave). A pointer activation sets the keyboard's active flag to false (its index is remembered); a keyboard activation does not touch the pointer state. `Tooltip active: false` never shows, `active: true` always does (`Tooltip.js:129`).
- **Values.** Stimulus reads values only from the controller element, so every `data-chadcn--chart-*-value` is written on `div[data-slot="chart"]` and nowhere else; the `svg` carries only `data-chadcn--chart-target="surface"`, and the `.recharts-wrapper` only `data-action`. A `Chart::Container` holds one chart (a second raises `ArgumentError`); the chart root hands its values and templates to the container it renders in (`claim_chart`, `append_after_shell`, `publish_chart_values`, all `@api private`).

Intended design (the server omits what recharts omits, so G2 stays an exact tree compare): recharts renders only the ticks `getTicks` keeps (`recharts:cartesian/getTicks.js:179`; `frame.rb` mirrors it with the server's assumed metrics), so the **controller never toggles visibility**: a hidden label would be a node recharts does not have. A second `turbo:before-cache` inside the snapshot window carries the first one's saved live state forward (`cancelled.state` of `primitives/turbo_cache.js`), and input is refused while `cache.pending`.

[n + start, 0].max : [start, n].min; to = stop.negative? ? [n + stop, 0].max : [stop, n].min; to > from ? s[from...to] : ""` (the Ruby kwarg form is `{slice: [start, stop]}`; `stop` is exclusive, a negative index counts from the end and is clamped to 0, an index past the end is clamped to the length, so `slice(-10, 3)` of `"January"` is `"Jan"` on both sides and an empty range is `""`; BMP text only, JS slices UTF-16 units and Ruby codepoints); `{"formatter": "locale"}` is `Number(v).toLocaleString("en-US")` and Ruby `:locale` (comma grouping, at most 3 fraction digits, no trailing zeros, half away from zero; a non-numeric value is returned as `String(v)`); `{"formatter": "percent"}` is `(Number(v) * 100).toLocaleString("en-US") + "%"` and Ruby `:percent`. ## DX helpers

**`spec_helpers.rb` derives nothing for chart**: `helpers_for` returns `nil` (`.claude/scripts/shadcn/spec_helpers.rb:51`) because the oracle exports no `Chart` root (`ChartContainer ChartTooltip ChartTooltipContent ChartLegend ChartLegendContent ChartStyle`), so chart is in the script's `no_parts` and the generated block is not written into this spec. `test/chadcn/chart_test.rb` is the only gate for the helpers below. Two generated sets (shadcn-port R16), neither hand-written:

1. **`Chart` root**, from `Chadcn::Base.const_added` (`lib/chadcn/base.rb:49-69`), which defines one root helper per **nested `Base` class**, not per oracle export: `container`, `style`, `tooltip`, `legend`, `bar_chart`, `line_chart`, `area_chart`, `pie_chart`, `radar_chart`, `radial_bar_chart`, and, because the declarations are also nested `Base` classes (`Chart::Bar`, ...), `bar`, `line`, `area`, `pie`, `cell`, `radar`, `radial_bar`, `x_axis`, `y_axis`, `cartesian_grid`, `polar_grid`, `polar_angle_axis`, `polar_radius_axis`, `label_list`, `label` (and `declaration` for the abstract base unless item #45 keeps it out of `Chart`; a declaration rendered outside a chart has nothing to register with, which #45 decides how to treat). Parts get their helper on their own namespace: `Chart::Tooltip::Content` yields `Chart::Tooltip#content` and `Chart::Legend::Content` yields `Chart::Legend#content`; there is **no** root `tooltip_content` / `legend_content`. `Chart::Tooltip#content` and `Chart::Legend#content` are the generated helpers: inside the block of a `Tooltip` or `Legend` the content registers with its declaration through the render context (`ContentSupport::HOLDER_KEY`) instead of drawing, so `chart.tooltip { |t| t.content(**kw) }`, `t.render Chart::Tooltip::Content.new(**kw)` and `content: Chart::Tooltip::Content.new(**kw)` render the same HTML; a second content, or one of the other kind, raises `ArgumentError`. `Chart::Config` is not a `Base` and has none. Helper names that shadow Phlex HTML elements (`style`, `legend`, `area`, `label`; `const_added` allows HTML element names, it raises for any other Phlex/Object method) are shadowed inside `Chart`'s own `view_template`, which therefore uses `tag(:style)` or explicit `render ...new` calls; the SVG itself is emitted by a separate surface component, not by `Chart` or by the chart classes' own view.
2. **Each chart class** (`BarChart`, `LineChart`, `AreaChart`, `PieChart`, `RadarChart`, `RadialBarChart`) yields itself and carries one helper per `Chart::Declaration` subclass: `bar`, `line`, `area`, `pie`, `cell`, `radar`, `radial_bar`, `x_axis`, `y_axis`, `cartesian_grid`, `polar_grid`, `polar_angle_axis`, `polar_radius_axis`, `tooltip`, `legend`, `label_list`, `label`. `const_added` cannot generate these (declarations are nested in `Chart`, not in the chart classes), so this is **new generator work** (items #45 / #48). Defining the helper "on every chart class" from `Declaration.inherited` would depend on load order: `Base.const_added` loads the nested parts in the order Zeitwerk registers them (`base.rb:49-58`, directory order, `Bar` before `BarChart`), so a `Declaration` subclass can be created before the chart classes exist and a test that eager loads would hide the gap. The helpers therefore live on **one module every chart class includes**, defined by `Declaration.inherited` (a method added to a module is visible to every class that already includes it), with the reserved-name check of `base.rb:63`:

```ruby
class Chadcn::Chart < Chadcn::Base
  # @api private
  module Declarations; end   # lib/chadcn/chart/declarations.rb; included by every chart class (BarChart, LineChart, ...)

  class Declaration < Chadcn::Base
    # @api private
    def self.inherited(subclass)
      super
      helper = subclass.name.split("::").last.gsub(/([a-z\d])([A-Z])/, '\1_\2').downcase.to_sym
      raise ArgumentError, "helper ##{helper} (from #{subclass}) would override a Ruby/Phlex API method" if Chadcn::Base.reserved_helper_names.include?(helper)

      # the class object is captured, so the helper does not depend on constant lookup order
      Declarations.define_method(helper) { |**attrs, &block| render subclass.new(**attrs), &block }
    end
  end

  class BarChart < Chadcn::Base
    include Declarations
  end
end
```

Each helper equals `render Chart::<Class>.new(...)`, so the example above renders the same HTML as the explicit calls. G2b (`parity_run.mjs --dx helpers`) runs only for components that `spec_helpers.rb --print` lists (R16), and chart has none, so the helper path is **not run against React** until the tree renderer's `dx: "helpers"` mode supports the harness-scoped `_` nodes (item #47); until then `test/chadcn/chart_test.rb` is the only gate and the deferred G2b is recorded in `deviations/chart.json`.

`test/chadcn/chart_test.rb` asserts both sets: set (1) against the nested `Base` classes of `Chart` (a new nested class without a helper, or a helper without a class, fails), set (2) against `Chart::Declaration.descendants` (same rule), and that every helper renders the same HTML as the explicit `render ...new`. It also has a **fresh-process test with the lazy loader** (no `eager_load`): a subprocess (`ruby -Ilib -e`) that requires `chadcn`, references **no declaration constant** and renders `Chadcn::Chart::BarChart.new(data: rows) { |chart| chart.bar(data_key: :a) }`, must succeed and equal the explicit-class render; a second one defines a `Declaration` subclass named like a Phlex method and expects `ArgumentError`.
