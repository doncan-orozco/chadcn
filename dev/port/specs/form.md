# Form (`Chadcn::Form`)

Oracle: `dev/port/oracle/src/form.tsx` (style `new-york-v4`, manifest `source_sha` `dfa22e6614b807df`, cited as `form.tsx:<line>`), manifest `dev/port/oracle/manifest/form.json`. Tier `third_party` (react-hook-form): there is no oracle DOM to compare, so the component is gated by Minitest and the browser tests of `chadcn--form`, not by G2 (`dev/port/deviations/form.json`). Decision, spike and alternatives: `dev/decisions/form.md`. Registry dependency: `label` (and, through the port, `field`, `input`).

Eight exports in the tsx: `useFormField`, `Form`, `FormItem`, `FormLabel`, `FormControl`, `FormDescription`, `FormMessage`, `FormField`. Only the ids/ARIA/data contract below is ported 1:1; the react-hook-form plumbing is replaced by a Binding.

```ruby
# Parts of Form::Field: nested classes, so Base.const_added generates field.<part> on Form::Field (shadowing the
# Chadcn::Field helpers it would inherit); shadcn-port R16, nothing is hand-written. Inside `Form::Field` the constants `Label`, `Description`, `Error` and the control names resolve to these nested classes, so the implementation references `Chadcn::Field::Label`, `Chadcn::Input` and the rest fully qualified. Each part reads its binding and
# attribute from the enclosing Form::Field through the render context; the caller never passes ids.
Chadcn::Form::Field::Label.new(**attrs)         # field.label: renders Chadcn::Field::Label with for:, data-error and the form.tsx:100 class
Chadcn::Form::Field::Control.new(**attrs)       # field.control { ... }: merges id/name/value/aria onto the caller's control (as_child style)
Chadcn::Form::Field::Description.new(**attrs)   # field.description: Chadcn::Field::Description with the description id
Chadcn::Form::Field::Error.new(**attrs)         # field.error: Chadcn::Field::Error with the message id; errors win over the block
Chadcn::Form::Field::Input.new(**attrs)         # #38: one class per bound control: Input, Textarea, Select, NativeSelect, Checkbox, Switch, RadioGroup, Slider, DatePicker, InputGroup
```

`Chadcn::Form` renders the only `<form>`; it is not used inside `form_with`. `Form#view_template` stores its binding in the render context around `yield` and restores the previous value in `ensure`, so nested forms work; `Form::Field` falls back to that value when `binding:` is nil. `class:` travels in `**attrs`, never as a declared kwarg, because `binding:` shadows `Kernel#binding`. `namespace:` prefixes every id (`"#{namespace}_#{id}"`, as Rails' `form_with namespace:`) so two forms with the same scope on one page do not share ids. `method:` other than get/post renders `method="post"` plus a hidden `_method`. A `get` form renders no CSRF input (the token would leak into URLs, logs and Referer). `model:` is the Plain binding's `object:` and nothing more: core never calls `model_name`, `errors` or `persisted?` on it, so `scope:` is required with `model:` (`ArgumentError` naming the missing kwarg otherwise) and errors come only from `errors:`. With `binding:`, every Plain-building kwarg (`scope:`, `model:`, `errors:`, `action:`, `method:`, `csrf_token:`, `namespace:`) raises `ArgumentError`; the binding is the single source. A Plain binding renders the CSRF input only when `csrf_token:` is given; a Rails view uses `Chadcn::Engine::FormBinding` (#40, README in #42), which reads errors, the token, the URL and the method from the model and the view context. `Form::Field` without `binding:` outside a `Form` raises `ArgumentError` ("Chadcn::Form::Field must be rendered inside Chadcn::Form or given binding:"), as form.tsx:52-54 throws. `namespace:` is applied by the binding only; `Form.new(namespace:)` is forwarded to the Plain binding it builds and is rejected together with `binding:`. `Plain` names the kwarg `http_method:` after the protocol message; `Form` and `FormBinding` say `method:` after the HTML attribute and `form_with`.

## Id / aria contract (the 1:1 core)

Per field the form generates `base`, one id unique per rendered field. React uses `React.useId()` (form.tsx:77); the port derives it from the binding (`binding.id_for(attribute)`, Rails and Plain agree: `user_email`), so it is stable across renders and unique per scope.

| Value | Rule | source |
|---|---|---|
| `form_item_id` | `"#{base}-form-item"`; the control's `id` and the label's `for` | form.tsx:61, 101, 113 |
| `form_description_id` | `"#{base}-form-item-description"`; the description's `id` | form.tsx:62, 131 |
| `form_message_id` | `"#{base}-form-item-message"`; the error's `id` | form.tsx:63, 149 |
| control `aria-describedby` | no error: `form_description_id`; with an error: `"#{form_description_id} #{form_message_id}"` (always lists the description id, even when no description is rendered, like React) | form.tsx:114-118 |
| control `aria-invalid` | `"true"` with an error, `"false"` without (React writes the boolean as a string) | form.tsx:119 |
| label `data-error` | `"true"` / `"false"`; the class `data-[error=true]:text-destructive` keys off it | form.tsx:99-100 |
| error content | when the field has errors: their messages (`errors_for` strings mapped to `{ message: }` for `Field::Error`), and the block is NOT passed (`Field::Error` lets a block win, form.tsx:140 lets the error win); no errors: the block; neither: renders nothing | form.tsx:140-145 |
| `name` / `value` | from the binding (`name_for`, `value_for`); no counterpart in the tsx (react-hook-form's `Controller` spreads them) | form.tsx:32-43 |

Deliberate difference from the Field port: `Chadcn::Field` writes no `data-invalid` by itself; with an error the bound field passes `data: { invalid: "true" }` to the root (Field's `data-[invalid=true]:text-destructive`) and `data: { error: }` plus `class: "data-[error=true]:text-destructive"` (a literal in `lib/chadcn/form/field.rb`, from form.tsx:100) to `field.label`.

## Structure

```html
<form data-slot="form" action method="post|get">   <!-- Form; hidden _method for put/patch/delete; CSRF input unless get -->
  <div role="group" data-slot="field" data-orientation data-invalid="true"> <!-- data-invalid only with an error -->   <!-- Form::Field = Chadcn::Field; tsx: FormItem <div data-slot="form-item" class="grid gap-2"> -->
    <label data-slot="field-label" for="{base}-form-item" data-error>   <!-- tsx: FormLabel, data-slot="form-label" -->
    <input id="{base}-form-item" name value aria-describedby aria-invalid data-slot="input">   <!-- tsx: FormControl Slot, data-slot="form-control" not rendered -->
    <p data-slot="field-description" id="{base}-form-item-description">   <!-- tsx: FormDescription, data-slot="form-description" -->
    <div role="alert" data-slot="field-error" id="{base}-form-item-message">   <!-- tsx: FormMessage <p data-slot="form-message"> -->
```

## Third-party

react-hook-form (`FormProvider`, `Controller`, `useFormContext`, `useFormState`) is not ported; its role is the server-side Binding (Plain, `Chadcn::Engine::FormBinding`). `zod` and `@hookform/resolvers` are out of scope; HTML5 constraint validation plus `chadcn--form` (#39) replace client validation.

## Dependencies

Registry: `label`. Port: `Chadcn::Field` (+ `Field::Label`, `Field::Description`, `Field::Error`), `Chadcn::Input`, `Chadcn::Textarea` and the other bound controls (#38). No runtime gem dependency; the Rails binding lives in the engine.

## Deviations

`dev/port/deviations/form.json`: the slots form-item, form-label, form-control, form-description and form-message are replaced by field, field-label, the control's own slot, field-description and field-error; FormMessage's `<p>` is `Field::Error`'s `<div role="alert">`; several messages render as a list; `chadcn--form` is house behavior. G1 cannot waive missing parts and slots today (decision, Open risks).

## Behavior

`chadcn--form` (#39): mirrors HTML5 validity (`checkValidity`, `validationMessage`) into the same `aria-invalid`, `aria-describedby`, `data-error` and message element on `input`/`change`/`invalid`, so a client-side error and a server-side error render the same markup. Server errors win on first paint; client validity takes over after the first edit. Without the controller everything above is still correct (server render only).

## Out of scope

Validation schemas (`zod`, `@hookform/resolvers`), `Controller` render props, `useFormState`, field arrays of react-hook-form. Nested attributes (#41) replace field arrays.
