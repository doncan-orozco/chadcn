# /shadcn-plan: oracle + plan for the full port

Arguments: $ARGUMENTS
Parse: `--only a,b` (subset), `--skip-tier t1,t2` (leave whole tiers out of the plan, e.g. `third_party`; the oracle and its audit still cover every component; the choice is stored in `state.json` and reused by `/shadcn-run` and by later runs of this command; `--skip-tier none` clears it), `--refresh` (re-fetch the registry), `--no-bootstrap` (skip catalog upgrade), `--lazy` (skip Phase 5, planners run just-in-time from `/shadcn-run`), `--dry-run` (stop after Phase 3 and print the plan).

Read `.ai/skills/shadcn-port/SKILL.md`, `references/parity-gates.md` and `references/infra-tasks.md` before starting. You are the orchestrator: you run scripts and dispatch `shadcn-port-planner`; you do not write component code.

The goal of this command is that `/shadcn-run` can run end-to-end with no human input afterwards. Everything ambiguous must be decided here and written down.

## Phase 0: Preflight (no agents)
1. `git status --short | head`; note the branch. Never commit. If on `main`, warn once in the final report (suggest a feature branch); continue.
2. Check `node -v` (>= 20), `ruby -v`, network (`curl -sI https://ui.shadcn.com/r/index.json`). No network and no `dev/port/oracle/registry`: stop with a clear message.
3. `mkdir -p dev/port/{oracle,specs,scenarios,deviations} tmp/shadcn-port`.
4. Create `dev/port/DEVIATIONS.md` if missing (header + empty table: component, deviation, reason, approved-by).
5. **Self-check of the tooling:** `ruby .claude/scripts/shadcn/command_lint.rb` must pass (every script, flag, subcommand, rake task, agent, slash command and reference named in the commands, agents and skills must exist). On findings STOP and report them: the docs are telling you to run something that does not exist.

## Phase 1: Oracle (script)
`ruby .claude/scripts/shadcn/oracle_extract.rb [--only ...] [--refresh]`. Expect ~60 manifests, `graph.json`, `VERSION.json`. Print the tier tally and any "skipped" lines (components absent from the style are reported, not failed). Then **audit the extraction**: `ruby .claude/scripts/shadcn/oracle_audit.rb` compares every manifest with an independent count from the TSX (cva tables, data-slots, components, class tokens, tiers). On findings STOP and report them: an extractor blind spot would silently weaken every gate. Record `dev/port/oracle/VERSION.json` digest in the final report.

## Phase 2: React catalog = the oracle (skip with `--no-bootstrap` when already verified) **Skipped entirely with `--dry-run`** (a dry run changes nothing outside `dev/port/` and `tmp/`).
The catalog is only a valid oracle if it runs exactly the registry source. Verify first:
`ruby .claude/scripts/shadcn/oracle_extract.rb --verify-catalog dev/react-shadcn-catalog/src/components/ui`.
If it passes, skip to Phase 3. Otherwise (first run, or the old Tailwind 3 / React 18 catalog):
1. In `dev/react-shadcn-catalog/`: move the current `src/components/ui` to `tmp/shadcn-port/old-catalog-ui/` (do not delete).
2. Upgrade stack to what the registry style needs: `react@19 react-dom@19 tailwindcss@4 @tailwindcss/vite tw-animate-css radix-ui lucide-react class-variance-authority clsx tailwind-merge@3`, dev: `shadcn typescript vite @vitejs/plugin-react @types/node` (Playwright is NOT installed here: `ruby .claude/scripts/shadcn/playwright_ensure.rb` installs the release that matches a Chromium you already have cached, or downloads one, and smoke-tests a real launch) and **pinned** `@types/react@19 @types/react-dom@19` (an unversioned install keeps the old v18 types and the CLI's `npm install` then fails with ERESOLVE on `@shadcn/react`); likewise `tailwind-merge@3` MUST be pinned: an unversioned install keeps the old `^2.x`, which only knows Tailwind 3 class names (`w-(--x)`, `outline-hidden`, `size-6!`) and makes the oracle's `cn` disagree with the Ruby gem on 3.4% of real merges (`cn_differential.rb`); remove `tailwind.config.js`, `postcss.config.js`, the per-package `@radix-ui/*` entries, `tailwindcss-animate`, `autoprefixer`, `postcss`. Use `npm install` (not `--force`). Playwright note: if the cached browser revision differs from the installed playwright's, install the matching version (`browsers.json` of `playwright-core`) or set `PARITY_CHROMIUM`.
3. `components.json`: style `new-york` (the CLI resolves it to the `new-york-v4` registry, same as the oracle), `rsc:false`, `tailwind.css: "src/index.css"`, `tailwind.config: ""`, `baseColor: "zinc"`, `cssVariables: true`, aliases as before. `vite.config.ts` uses `@tailwindcss/vite`, alias `@` -> `src`, alias `@scenarios` -> `../port/scenarios`, alias `@host-theme` -> `../../app/assets/tailwind/chadcn` (the gem's shipped theme, also read by the dummy app), `server.fs.allow: ["..", "../.."]`, `tsconfig.json` with `"moduleResolution": "bundler"` (the old `node` resolution cannot read package `exports`, so `@shadcn/react/message-scroller` fails to type-check), and a **dev base of `/`**: `base: command === "build" ? "/react-catalog/" : "/"` (the old fixed `/react-catalog/` base makes the dev server answer only under that path, so `http://localhost:5173/#/parity/...` would not exist).
4. **Do NOT run `shadcn init`** (the current CLI offers bases/presets such as `base-nova` and may rewrite `components.json` to a different style than the oracle). Write `src/index.css` yourself: `@import "tailwindcss"; @import "tw-animate-css"; @import "@host-theme/theme.css"; @import "@host-theme/tokens.css";`. Vendor the CSS the registry depends on with `ruby .claude/scripts/shadcn/theme_sync.rb --vendor`. Token coverage is verified later by `theme_sync.rb --check-tokens` (compiles every semantic class the oracle uses).
5. Install the components by **explicit name**, never `--all`: `npx shadcn@latest add $(ls dev/port/oracle/manifest | sed 's/\.json$//') --overwrite --yes`. `--all` aborts the whole install when one index entry (e.g. `questionnaire`) is absent from the style; the manifests only contain what the style really has. If the CLI still reports an item as missing, drop that name, record it in the report, and retry once.
   **5b. Restore `src/index.css` right after the install.** The CLI rewrites it (it appends the sidebar variables in HSL, a second `@custom-variant dark` and a second `@theme inline`); in the React catalog those HSL values would override the host theme's OKLCH ones, so sidebar components could never match the Phlex side. Overwrite it again with the four imports from step 4. `house_check.rb` fails (`G5_CATALOG_CSS`) if it ever contains `:root`, `.dark` or `@theme`.
6. Re-run `--verify-catalog`. Any `G0_CATALOG_DRIFT` => fix the catalog (re-add that item) until clean; never edit oracle files to match the catalog.
7. `npm run build` must pass (type check + production build), and `npm run dev -- --port 5173` must answer `GET /` with 200. Rehearse all of Phase 2 on a scratch copy first, touching nothing in the repo: `bash .claude/scripts/shadcn/catalog_rehearsal.sh`. Keep `App.tsx` as the visual catalog but the harness (`_harness` task) mounts under `#/parity/...`.

## Phase 3: Theme + plan state (scripts)
1. Presets exist already; regenerate only with `--refresh`: `ruby .claude/scripts/shadcn/theme_sync.rb --emit-presets`. Run `bin/rails theme:check` and report warnings (the host `theme.css` must be zinc at this point unless the user changed it). `--emit-presets` regenerates the GEM's presets only; the host's presets are copies, so run `rails g chadcn:install` afterwards to re-copy them (otherwise they drift).
2. `ruby .claude/scripts/shadcn/port_state.rb init [--only ...] [--skip-tier ...]` (it refuses a skip that would leave an included component depending on a skipped one) (keeps existing statuses when re-run with the same oracle digest; if the digest changed, mark every component whose `source_sha` changed as `pending`, and say which).
3. `ruby .claude/scripts/shadcn/port_state.rb summary` and show the wave table. Wave 0 infra, then pilot (button, switch, tooltip, dropdown-menu, select; then dialog), then fan-out waves in dependency order.
`--dry-run`: stop here and print (including which components `--skip-tier` left out): waves, tier tally, third-party libraries needed (union of manifests' `third_party`) and which are already pinned in `config/importmap.rb` (flag the missing ones as pin tasks for the matching components).

## Phase 4: Migration map of the legacy components (no agents, informational)
The port is from scratch in `lib/chadcn/`; legacy `app/components/ui/*` stays untouched. For every legacy `app/components/ui/*.rb` that has a manifest, count callers (`grep -rln "Components::Ui::<Class>" app test ../papyro_studio/app ../papyro_studio/test`) and write `dev/port/CALLERS.md` (component, legacy file, caller count, top 5 callers). It is only for the later Ui -> V2 migration and is NOT given to planners or builders.

## Phase 5: Per-component planning (agents, skipped with `--lazy`)
Dispatch `shadcn-port-planner` for every component in state `pending`, in parallel blocks of at most 6, ordered by wave (pilot first so problems surface early). Prompt per component (self-contained, include):
- `COMPONENT`, manifest path, src path, `TIER`, `registry_dependencies` already planned/DONE (names only), existing primitives list, and the instruction that `app/components/ui/*` must not be read.
Budget (measured on real runs, opus): static/simple components 35-50k tokens and 1-2 min each; overlay/menu/select 110-175k tokens and 7-11 min each (they read the Radix sources), so the 50 core components cost roughly 3-4M tokens; the 11 `third_party` ones more. Collect each JSON receipt, then **validate the output yourself, never trust the receipt**: `ruby .claude/scripts/shadcn/planner_check.rb --component <name>` (spec sections, every part and data-slot named, scenario JSON shape, React-named props, valid steps, enough scenarios, full variant/state coverage, deviations with a reason). On findings, send them back verbatim (max 30) to the planner ONCE; if still failing keep the component `pending` with `--note "planner_check: <codes>"`. Only a passing check -> `port_state.rb set <name> planned`. After the batch run `ruby .claude/scripts/shadcn/spec_helpers.rb --all` (appends the derived "DX helpers" section to every compound component's spec; idempotent; zero LLM cost) and `ruby .claude/scripts/shadcn/deviations_register.rb` so every `deviations/<name>.json` a planner wrote is listed in `DEVIATIONS.md` (the G5 house check fails an unregistered deviation). On `blockers` -> keep `pending` with `--note`. Re-dispatch a planner once if its receipt is malformed. Never re-plan `planned/built/done` unless `--refresh` changed its `source_sha`.

## Phase 6: Plan report
Write `dev/port/PORT_PLAN.md`: oracle version/digest; wave table (from `port_state.rb summary`); per component: tier, #scenarios, planned deviations, third-party libs; the blockers list; estimated run size (components x average scenarios). End with the exact next command: `/shadcn-run all`.

## Rules
- Idempotent: running twice changes nothing unless the oracle changed.
- Planners only write spec/scenarios/deviations; verify with `git status` that no other files changed after Phase 5.
- Do not start servers here; do not build components here.
